Prepare 深挖：副作用前最后一道门

	
prepare 的任务不是“准备执行代码”，而是证明这次调用有资格进入 execute。顺序必须是 find → validate → hook → abort → block → prepared。

	

		
关键片段 · 每个出口都返回数据，不执行工具

export async function prepareToolCall(options) {
  const tool = options.tools.find(
    ({ name }) => name === options.toolCall.name
  );
  if (!tool)
    return immediate(
      options,
      errorResult(`Tool "${options.toolCall.name}" not found`)
    );

  const issues = validateJsonSchema(
    options.toolCall.arguments,
    tool.parameters
  );
  if (issues.length > 0) {
    const details = issues
      .map(({ path, message }) => `${path}: ${message}`)
      .join("; ");
    return immediate(
      options,
      errorResult(
        `Tool "${tool.name}" arguments failed validation: ${details}`
      )
    );
  }

  let beforeResult;
  try {
    beforeResult = await options.beforeToolCall?.({
      assistantMessage: options.assistantMessage,
      toolCall: options.toolCall,
      args: options.toolCall.arguments,
      messages: options.messages.slice(),
    }, options.signal);
  } catch (error) {
    return immediate(options, errorResult(
      error instanceof Error ? error.message : String(error)
    ));
  }

  if (options.signal?.aborted)
    return immediate(options, errorResult("Operation aborted"));
  if (beforeResult?.block) {
    const result = errorResult(
      beforeResult.reason ?? "Tool execution was blocked"
    );
    if (beforeResult.terminate === true)
      result.terminate = true;
    return immediate(options, result);
  }
  return {
    kind: "prepared",
    toolCall: options.toolCall,
    tool,
    args: options.toolCall.arguments,
    startedAt: options.startedAt,
  };
}

Execute 深挖：副作用、update queue 与竞态

	
execute 的第一行必须重新检查 signal。prepare 与 execute 之间存在一次异步切换，用户可能恰好在这个缝隙按下 Ctrl+C。

	

		
关键片段 · update 不是 Promise.all 并发，而是一条串行链

export async function executePreparedToolCall(
  prepared,
  signal,
  onUpdate,
) {
  if (signal?.aborted) {
    const result = errorResult("Operation aborted");
    return {
      toolCall: prepared.toolCall,
      result,
      isError: true,
      startedAt: prepared.startedAt,
    };
  }

  let updateQueue = Promise.resolve();
  let acceptingUpdates = true;
  let result;

  try {
    const executed = await prepared.tool.execute(
      prepared.args,
      signal,
      (partial) => {
        if (!acceptingUpdates) return;
        const update =
          updateQueue.then(() => onUpdate(partial));
        update.catch(() => {});
        updateQueue = update;
      },
    );
    acceptingUpdates = false;
    result = {
      content: executed.content ?? [],
      isError: executed.isError === true,
      terminate: executed.terminate,
    };
  } catch (error) {
    acceptingUpdates = false;
    result = errorResult(
      error instanceof Error ? error.message : String(error)
    );
  }

  await updateQueue;
  return {
    toolCall: prepared.toolCall,
    result,
    isError: result.isError === true,
    startedAt: prepared.startedAt,
  };
}

7
回测：用“反过来会怎样”检查是否真的理解

	

		
1. 为什么不能在 execute 内再做权限判断？
因为进入 execute 就已经跨过统一的副作用边界；每个工具还会各自重复校验/权限逻辑，无法保证所有工具都在副作用前被拦截。

		
2. 为什么 block 不是 throw？
block 是模型能修的业务结果。回喂 toolResult 后模型可以换方案；throw 会把它误判成宿主 runtime failure。

		
3. 为什么 update 需要串行 Promise 链？
只用 Promise.all 保证 end 等全部完成，却不保证 update #1 在所有 listener 中都先于 #2；串行链同时保证 source order 与 end barrier。

		
4. 为什么 finalize 必须同时处理 immediate 与 executed outcome？
这样 unknown、invalid、blocked、throw 与成功路径都产生同一事件/消息协议；UI 和历史无需为失败来源写特判。

		
5. 为什么 execute 前还要再检查 abort？
prepare 与 execute 之间有 await/microtask 缝隙。用户可能在 prepare 返回后中止；不复查就可能继续执行忽略 signal 的副作用工具。

		
6. 为什么 prototype 属性也要用 Object.hasOwn？
in 会把继承的 toString/constructor 当成真实参数，导致 required 或 additionalProperties 校验被绕过；JSON 参数必须只看 own properties。
