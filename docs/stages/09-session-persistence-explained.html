AgentSession：包住执行入口

submission 先持久化，再 prompt。内部 awaited listener 先存 assistant、工具结果和 run_end，再让外部订阅者观察。CLI 默认新建，--continue 恢复当前目录最新文件。

submission + fsync → assistant + fsync → prepare
→ tool_intent + fsync → execute → tool_outcome + fsync
→ toolResult message + fsync → run_end + fsync

“没有 outcome”不等于“没有副作用”。intent 是执行可能发生的证据，不是执行已经成功的证据。parallel 必须先提交全批 intent，才能启动任一 execute。

03 / 树不是文件最后几行

	
A → B → C    旧分支仍在文件
└→ D → E    当前 leaf = E

物理顺序：A, B, C, D, E
当前路径：A, D, E

	
branch(A) 只移动内存 leaf；下一条 D 的 parentId 指向 A。reopen 默认选择物理最后一条有效 entry，再走 parent 链。全 session 的 requestId 去重读所有 entry，不只读当前路径。


	
04 / 恢复规则，不是猜测

	

		
日志证据恢复动作为什么

		
			
toolCall，没 intent补未到执行边界的 error只有 prepare 成功后才允许提交 intent

			
safe intent，没 outcome声明匹配且当前仍 safe 才重跑工具作者允许重跑；不保证数据不变

			
unsafe／工具缺失／声明变化partial + interrupted error不能把未知副作用放大成重复执行

			
outcome，没有 message只补 toolResultdurable 结果已经存在

			
最终 assistant，没有 run_end按 stopReason 补 run_end无需再生成一次模型回复

		
	

	
内置 read = safe；edit / bash = unsafe；默认 unsafe。unsafe 的 partial content 是已记录的观察，不是副作用完成证明。replay 声明不能产生跨外部系统的 exactly-once。

	
级别 2：修复到完整 turn 边界。不做任意 step checkpoint、provider 自动生成恢复、task graph、compaction、/fork 或 CLI 树选择器。只有 submission 的崩溃保留 user-only 历史，不自动重发。

	
torn tail：仅忽略末尾无换行且无法解析的一条 fragment；中间坏 JSON、换行结束的坏 JSON、重复 id、缺 parent、未知版本必须报错。这不是“坏数据都跳过”。


	
05 / 换个设计，会失去什么？

	

		
覆盖 session.json？
旧历史被反复触碰，写一半可能毁掉快照；branch 和审计也失去共同事实。

		
execute 后再记 intent？
最需要日志的窗口恰好没有日志：命令已跑，进程死了，重启只能猜。

		
pending 全部重跑？
可能把文件改两次，把命令执行两次。safe / unsafe 是副作用决策，不是性能选项。

		
幂等键只放内存？
一重启就忘了。同一个请求可能再次调模型和工具；按 active branch 去重也会漏掉旧分支。
