# Web UI V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为当前阶段 6 的 mini-agent 增加一个 localhost 单用户 Web 工作台，让用户通过 deterministic Demo 操作一次 run，并在 Light 三栏界面中观察聊天、工具调用和按 Turn 分组的完整 Timeline。

**Architecture:** 新增 `protocol`、`server`、`web` 三个包。Server 通过 core 公共 `Agent` API 创建单 Run Demo，给原始 `AgentEvent` 包装 `runId / sequence / elapsedMs` 后经 WebSocket 发送；React Web 只消费共享 protocol，通过纯 reducer 同时派生 Chat、tool cards 与 Timeline，不 import core 或 server。

**Tech Stack:** TypeScript 5.9.3（`strict` + `erasableSyntaxOnly`）、Node 22+、pnpm workspaces、Vitest 3、React、Vite、`ws`、Testing Library、jsdom。Web/Server 可新增运行时依赖，`core` 与 `ai` 的依赖边界保持不变。

**Spec:** `docs/specs/2026-10-12-web-ui-v1-design.md`

## Global Constraints

- V1 只绑定 `127.0.0.1`，只支持本机单用户，不做 auth、多租户或公网部署。
- 一次只观察一个 run；新 run 清空上一 run 的 Chat、Timeline 和 selected event。
- Session 为 ephemeral；刷新、server 重启或 WebSocket 断开后不恢复。
- Fake 阶段采用 Prompt + 显式 Demo 场景；Prompt 进入 transcript，但场景脚本决定 provider 行为。
- 不提前实现真实 provider、reasoning block、持久化、文件树、diff、终端、子 Agent 或扩展 UI。
- Web 采用已批准的 Light 三栏布局，不实现 Dark 主题。
- Timeline 默认打开并按 Turn 分组；连续 `message_update` 只在视图层聚合，原始 envelopes 必须保留。
- Chat tool cards 按 assistant 源顺序；Timeline 的 `tool_execution_end` 按真实 sequence。
- Server 不改写 `AgentEvent`，只包装 `{ runId, sequence, elapsedMs, event }`。
- `web` 不 import `core` 或 `server`；`server` 不 import core 内部文件。
- `protocol` 仅通过 `import type` 使用 core 公共 `AgentEvent`，破坏性 event wire 变化必须提升 protocol version。
- 所有 ClientCommand 都必须做 runtime shape validation；invalid input 不能启动假 run。
- `erasableSyntaxOnly: true`：禁止 `enum`、构造函数参数属性和 `namespace`；类型导入必须 `import type`。
- 跨包导入用包名，包内相对导入带 `.ts` / `.tsx` 后缀；tab 缩进。
- 每个 `src` 文件 < 200 行；注释只解释非显然的“为什么”。
- `pnpm test` 与 `pnpm check` 必须全绿。

## Review Focus

1. **Malformed / oversized WebSocket input**：必须返回具名 protocol error 或关闭连接，不能 crash server。→ Task 4。
2. **Single-flight boundaries**：active run 期间第二个 start 与 reset 必须被拒绝，abort 必须等真实 lifecycle settle。→ Task 3。
3. **Disconnect during a run**：必须 abort active Agent、丢弃 ephemeral session，不能向新连接补发成功状态。→ Tasks 3、4。
4. **Unknown or out-of-order events**：Web 必须保留 raw envelope 并显示 diagnostic，而不是丢事件或崩溃。→ Task 5。
5. **Parallel dual ordering**：Timeline 必须保持 completion sequence，Chat/toolResult 必须保持 assistant source order。→ Tasks 2、5。

### Task 3: 实现 Single-Run SessionController

**Files:**
- Create: `packages/server/src/session-controller.ts`
- Create: `packages/server/test/session-controller.test.ts`

**Interfaces:**
- Consumes:
  - `DemoScenarioRegistry` from Task 2
  - `ClientCommand` / `ServerMessage` from Task 1
- Produces:

```ts
export type ServerMessageSink = (
	message: ServerMessage,
) => void | Promise<void>;

export interface SessionControllerOptions {
	send: ServerMessageSink;
	scenarios: DemoScenarioRegistry;
	createRunId?: () => string;
	now?: () => number;
}

export class SessionController {
	constructor(options: SessionControllerOptions);
	sendReady(): Promise<void>;
	handle(command: ClientCommand): Promise<void>;
	disconnect(): void;
}
```

构造函数必须显式声明字段，不使用参数属性。

- [ ] **Step 1: 写 `server.ready` 与正常 run 的失败测试**

断言：

- `sendReady()` 发送 protocol version、V1 capabilities 和 registry summaries。
- `run.start` 先发送 `run.accepted`，再发送任何 `agent.event`。
- envelope sequence 从 0 严格递增。
- 注入递增 `now()` 后 elapsedMs 非负且不倒退。
- 正常 terminal message 产生 `run.settled: completed`。

- [ ] **Step 2: 写 single-flight / reset / outcome mapping 失败测试**

覆盖：

- active run 再 start → `protocol.error` code `RUN_ACTIVE`。
- active run reset → `protocol.error` code `RUN_ACTIVE`。
- idle reset → `workspace.reset` acknowledgement。
- terminal stopReason `aborted` → settled `aborted`。
- terminal stopReason `error` → settled `error`。
- send listener 在中途 reject 一次但之后可接收 → settled `failed`，且不伪造额外 `agent_end`。

- [ ] **Step 3: 写 abort / disconnect 失败测试**

覆盖：

- 无 active run abort → `NO_ACTIVE_RUN`。
- active run abort 只调用 `agent.abort()`；settled 必须等待真实 aborted lifecycle。
- `disconnect()` abort active run、清空 controller；随后旧 run 不得向 sink 发送成功 settled。

- [ ] **Step 4: 运行测试确认失败**

Run:

```bash
pnpm --filter @mini-agent/server run test -- session-controller
```

Expected: FAIL，因为 SessionController 尚不存在。

- [ ] **Step 5: 实现 controller**

关键规则：

- `run.start` 清空上一 run 引用，创建 fresh Agent。
- 发送 `run.accepted` 后再 subscribe/prompt。
- Agent listener 逐条 await sink。
- 保存最后一条 completed assistant `message_end.stopReason`，在 prompt settle 后映射 transport outcome。
- infrastructure failure 映射 `failed`。
- `disconnect()` 设置 closed 标志；closed 后 `send` 不再调用外部 sink。
- `run.start` 不 await 整个 prompt 后才返回；controller 保存内部 run promise，使后续 abort command 能并发到达。

```ts
	lastProtocolError?: { code: string; message: string };
}

export type AppAction =
	| { type: "connection.changed"; connection: AppState["connection"] }
	| { type: "server.message"; message: ServerMessage }
	| { type: "scenario.selected"; scenarioId: string }
	| { type: "prompt.changed"; prompt: string }
	| { type: "timeline.selected"; itemId?: string }
	| { type: "workspace.cleared" };

export function createInitialAppState(): AppState;
export function reduceAppState(state: AppState, action: AppAction): AppState;
export function buildTimeline(
	envelopes: AgentEventEnvelope[],
): TimelineItem[];
export function buildChatView(
	envelopes: AgentEventEnvelope[],
): ChatItem[];
```
